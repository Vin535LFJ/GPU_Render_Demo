# 文档2：系统架构设计文档（AD）
## 1. 架构总览
采用**三层分层架构**，职责隔离、可扩展、可测试。

## 2. 分层设计
### 2.1 SDK Facade层（Kotlin）
- 职责：对外暴露API、生命周期绑定、业务交互
- 核心类：PlayerView、Player、Clip、Config、Callback
- 约束：业务仅依赖该层

### 2.2 Runtime层（Kotlin+JNI）
- 职责：时间线调度、资源编排、状态机管理、Native桥接
- 核心模块：Timeline、StateMachine、JNI Bridge
- 约束：无GL操作、无编解码细节

### 2.3 Engine Core层（C++）
- 职责：OpenGL渲染、纹理/FBO管理、RenderGraph、编解码、导出、时钟同步
- 核心模块：Decode、TextureBridge、RenderGraph、LayerComposer、AudioClock、ExportPipeline

## 3. 模块依赖图
App → SDK Facade → Runtime → JNI → Native Engine

## 4. 核心流程架构
### 4.1 实时预览架构
AudioClock → TimelineTick → LayerResolve → RenderGraph → Present
### 4.2 离线导出架构
ExportClock → TimelineTick → Offscreen RenderGraph → EncoderSurface → MediaMuxer

## 5. Runtime Ownership Matrix（冻结回填）
### 5.1 线程Owner
- UI线程：仅发送控制命令（play/pause/seek/stop/release）
- Runtime控制线程：状态迁移校验与命令编排
- DecodeThread：MediaCodec dequeue/flush/seekTo
- RenderThread：EGL/GL/SurfaceTexture ownership、render submit、frame queue consume

### 5.2 禁止跨线程动作
- 非RenderThread禁止调用：`eglMakeCurrent`、`updateTexImage()`、SurfaceTexture attach/detach
- 非DecodeThread禁止调用：MediaCodec `flush/dequeue`
- 非Runtime控制线程禁止直接改状态机状态

### 5.3 失败策略
- 违反ownership：返回 `E_RUNTIME_CONTRACT_BREACH` 并记录告警；fatal场景进入 stop/release 收口路径

## 6. 生命周期冻结回填
### 6.1 RenderGraph生命周期
`INIT -> CONFIGURED -> RUNNING -> RECONFIGURING -> RUNNING -> RELEASED`

### 6.2 EGL / SurfaceTexture生命周期归属
- EGLDisplay/EGLContext/EGLSurface：仅RenderThread创建与销毁
- SurfaceTexture生命周期：`CREATED -> ATTACHED -> ACTIVE -> DETACHED -> RELEASED`
- context lost重建顺序：OES texture -> SurfaceTexture -> shader program -> FBO -> VAO/VBO

## 7. 技术选型依据
- 渲染：OpenGL ES3.x（Android生态最成熟）
- 编解码：MediaCodec（硬解最优）
- 同步：Audio主时钟（音画同步最优）
- 导出：离屏FBO（保证所见即所得）
