# 文档6：音视频同步与渲染流程设计文档
## 1. 时钟同步策略（冻结）
### 1.1 主时钟
- 默认：AudioClock（音频播放时间戳）
- 无音频：System monotonic clock

### 1.2 同步规则
1. 视频帧按PTS对齐主时钟
2. 动画帧按时间t直接计算索引
3. `|drift| < 20ms`：稳定区，不调速不丢帧
4. `20ms <= |drift| <= 80ms`：平滑纠偏区，仅调速
5. `|drift| > 80ms`：强纠偏区，允许受控丢帧/追帧

### 1.3 调速与防振荡
- 正漂移调速范围：`1.00 ~ 1.03`
- 负漂移调速范围：`0.97 ~ 1.00`
- 单次调速步长上限：`0.005`，每100ms最多1次
- 连续drop上限：3帧；达到上限后进入200ms平稳窗口（仅调速）
- 300ms内禁止“调速->丢帧->调速”重复切换超过2次

## 2. 实时预览流程
1. AudioClock获取当前时间t
2. Timeline计算t对应的帧/图层/特效
3. DecodeThread输出帧到SurfaceTexture
4. RenderThread执行 `updateTexImage` 并转换为OES纹理采样
5. RenderGraph执行多Pass渲染
6. 合成结果上屏

## 3. 离线导出流程
1. 启动固定步进ExportClock
2. 逐帧tick时间线
3. 离屏FBO渲染
4. 帧数据送入编码器
5. 音视频数据封装为MP4

## 4. Seek Recover流程（冻结）
状态流：
`PLAYING/PAUSED -> SEEK_REQUESTED -> SEEK_FLUSHING -> SEEK_PRIMING -> SEEK_RECOVERING -> PLAYING/PAUSED`

步骤：
1. Runtime标记 `SEEK_REQUESTED`，阻断render submit
2. 进入 `SEEK_FLUSHING`：仅此状态允许触发decoder flush
3. DecodeThread执行：`codec.flush + extractor.seekTo(keyframe)`
4. 清空frame queue并prime首批可显示帧，进入 `SEEK_PRIMING`
5. AudioClock按targetUs重锚点，进入 `SEEK_RECOVERING`
6. 满足recover条件后回到 `PLAYING/PAUSED`

recover条件：
- 至少1帧有效视频帧
- AudioClock重锚点完成

recover超时与失败策略：
- 超时阈值：500ms
- 超时处理：返回 `E_RECOVER_TIMEOUT`，降级到 `PAUSED`

## 5. Flush Gate与释放顺序（冻结）
### 5.1 Flush allowed-state gate
- 仅 `SEEK_FLUSHING` 与 `STOPPED` 允许触发decoder flush

### 5.2 Release destroy order
1. stop clock
2. stop render submit
3. flush decoder
4. clear frame queue
5. detach SurfaceTexture
6. destroy GL resource
7. destroy EGL
8. stop thread
