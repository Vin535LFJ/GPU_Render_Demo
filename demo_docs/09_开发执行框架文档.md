# 文档9：开发执行框架文档（冻结版 Implementation Roadmap）

## 1. 项目目标与范围边界
### 1.1 目标
在不进入完整功能实现细节的前提下，完成“设计冻结 + 执行框架”定义，确保团队可按分期直接开发，避免因核心架构未冻结导致返工。

### 1.2 技术基线（冻结）
- Kotlin + JNI + C++17 + OpenGL ES 3.x + MediaCodec
- 最小链路：MP4 → MediaCodec → SurfaceTexture → OES Texture → RenderGraph → GLSurfaceView

### 1.3 范围边界
- 本文档不引入新架构，不进入具体代码实现。
- 本期不引入：protobuf / ECS / plugin system / Vulkan。

---

## 2. 设计冻结项与允许后置项
### 2.1 P0 必须冻结项（开发前置）
1. seek 状态机（状态、转换、非法调用处理）
2. decoder flush 时序（含关键帧对齐与渲染恢复）
3. GL thread ownership（唯一 owner 与跨线程调用边界）
4. EGL / SurfaceTexture 生命周期（创建、绑定、重建、销毁）
5. AV sync drift 策略（参数化阈值、纠偏、防振荡）
6. RenderGraph 生命周期（init/reconfigure/render/release）
7. release destroy order（停时钟→停渲染→停解码→释放 GL/EGL）
8. 量化验收指标（P50/P95/P99、漂移、丢帧、稳定性）

### 2.2 P1 可后置项（不阻塞最小链路）
1. GPU compatibility matrix
2. colorspace 完整策略
3. FBO reuse 精细化策略
4. SurfaceTexture 机型差异策略
5. 机型分层策略

---

## 3. 分期计划（先稳链路，再扩特效与导出）
### P0（冻结阶段）
- 目标：冻结核心设计口径，消除冲突项与未定义项
- 结果：00~08 文档形成可执行一致版本

### P1（最小链路落地）
- 目标：打通 MP4→解码→纹理→RenderGraph→上屏链路
- 结果：可稳定预览，具备基础可观测指标

### P2（同步与稳定性）
- 目标：完成 AV sync 参数化、seek recover、release 稳定性闭环
- 结果：高频 seek、暂停恢复、后台切换可控

### P3（特效与导出扩展）
- 目标：在稳定链路上扩展 shader 特效链与离屏导出
- 结果：预览/导出一致性可量化验收

---

## 4. 每期输入 / 输出 / 依赖 / 风险
### P0
- 输入：00~08 现有文档
- 输出：冻结规则、冲突清单关闭、执行口径统一
- 依赖：架构评审结论、团队共识
- 风险：冻结不彻底导致后续返工

### P1
- 输入：P0 冻结后的 00~08
- 输出：最小链路可运行 + 指标采集框架
- 依赖：线程模型、生命周期、状态机冻结完成
- 风险：机型差异引发 OES / SurfaceTexture 问题

### P2
- 输入：P1 稳定链路
- 输出：同步纠偏策略落地、seek 稳定恢复、释放顺序固化
- 依赖：解码与渲染可观测数据
- 风险：漂移纠偏振荡、状态竞争导致偶发崩溃

### P3
- 输入：P2 稳定基线
- 输出：特效链扩展、离线导出、预览导出一致性验证
- 依赖：RenderGraph 生命周期与 FBO 复用策略
- 风险：性能回退与一致性偏差

---

## 5. 量化验收标准
1. 链路可用性：最小链路成功率 100%（定义素材集）
2. 性能预算：CPU/GPU/decode/upload 分项预算，含 P50/P95/P99
3. 同步指标：AV drift 分布、纠偏触发率、连续丢帧上限
4. 稳定性：高频 seek、长时播放、前后台切换无崩溃/黑屏
5. 一致性：预览与导出帧级一致性（阈值化定义）

---

## 6. 里程碑前置关系
- P0 是 P1 的前置阻断条件（未冻结不进入实现）
- P1 完成后方可进入 P2（无稳定链路不做同步优化）
- P2 完成后进入 P3（无稳定同步不扩特效/导出）

---

## 7. 需要先修改的文档（00~08）
1. 00：统一 C++17、性能预算口径、资源释放时序
2. 01：补异常矩阵（VFR/B帧/后台/来电/损坏流/EOS）
3. 02：补 RenderGraph 生命周期、GPU 兼容策略、线程 ownership
4. 03：补 AV sync 参数化、seek 状态机、线程模型
5. 04：补 JNI 版本化、错误码、callback 线程约束、结构化参数
6. 05：补 CPU/GPU/decode/upload 预算与 P50/P95/P99
7. 06：补防振荡、seek recover、release destroy order
8. 07：补量化验收标准
9. 08：统一 C++17、NDK/AGP/Kotlin 版本矩阵、线程规范

---

## 8. 暂不实现项（避免过度设计）
1. Vulkan 渲染链路
2. protobuf 协议化改造
3. ECS / plugin system 架构升级
4. 重型 AI 特效（分割、超分、美颜）
5. 多轨复杂 NLE 能力

---

## 9. 执行原则
1. 先冻结核心链路，再进入实现；冻结不完整不得开工。
2. 先稳定最小链路，再扩展特效与导出。
3. 每期必须满足“输入清晰、输出可验收、依赖可追踪、风险可回滚”。
4. 所有关键结论必须落回 00~08 对应文档，保持单一事实来源。
5. 每个里程碑以量化指标作为“完成”判据，避免主观验收。
